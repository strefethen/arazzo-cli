Know why a workflow output is null

When an action skips a step referenced by a workflow output, JSON consumers now receive the missing-value warning. The explanation survives child workflows, dry runs, parallel execution and later failures.

Before · run --json, default mode

{
  "kind": "success",
  "outputs": {"skippedStatus": null}
}

The warning appeared only on stderr. A program reading JSON could not distinguish an unresolved expression from a real null.

After · same workflow and output value

{
  "kind": "success",
  "outputs": {"skippedStatus": null},
  "warnings": [
    "workflow \"serial\" output \"skippedStatus\": $steps.skipped.outputs.status: step \"skipped\" not found in context"

}

The warning identifies the workflow, output, expression and cause. JSON mode emits no duplicate warning on stderr.

Applications embedding the engine can now supply their own SourceDocumentLoader. It receives the source name and the resolved local path, then supplies bytes or an error. Callers can serve a document from memory or reject a read before native file access occurs.

Before · engine-owned read

  → read file directly
  → parse and index

After · caller-owned acquisition

Resolve local source
  → custom loader or native loader
