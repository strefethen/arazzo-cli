# JSON run export (`run.v1`)

`arazzo-cli run <spec> <workflow-id> --export-run <path>` writes a JSON artifact for inspecting declared workflow data and every settled step execution. Use `arazzo-cli schema export-run` for its JSON Schema; the distributed copy is [`schemas/export-run.schema.json`](schemas/export-run.schema.json). `--export-run` can be combined with `--json`, `--dry-run`, `--step`, `--parallel`, and `--trace` (at a different path). It does not alter normal stdout.

The root object contains `schemaVersion: "run.v1"`, `tool` (`name`, `version`), `run`, `inputs`, `outputs`, and `workflows`. `inputs` holds parsed command-supplied values before the engine applies workflow defaults. `run` has `specPath`, `workflowId`, optional `stepId`, `parallel`, `dryRun`, `startedAt`, `finishedAt`, `exportedAt`, `durationMs`, `status`, and optional `error` (`code`, `message`). The three timestamps are RFC 3339 UTC. `startedAt` and `finishedAt` bracket execution, `exportedAt` marks artifact production, and `durationMs` uses a monotonic timer.

`run.status` is `success`, `failure`, or `dryRun`. It reports the **runtime result**. A later CLI expression-diagnostic policy error or trace/export write failure can make the command exit nonzero without changing the runtime status in an artifact that was written. A failed or timed-out runtime run has `run.error` and empty final `outputs`, while retaining attempts that completed or settled. Setup and parse failures before execution do not promise an artifact. An export write failure exits nonzero; with `--json`, the ordinary run error envelope carries `code: "RUN_EXPORT_WRITE"`. It preserves the runtime and trace failure messages when those also occur. Missing parent directories are errors; the writer replaces a file atomically and does not leave partial JSON.

`workflows` is keyed by workflow ID. Each workflow has `steps`, keyed by step ID; each step has an ordered `executions` array. Every execution has a global `sequence` (capture emission order), a 1-based `attempt` ordinal for that workflow/step pair, `outcome` (`success`, `failure`, or `dryRun`), `durationMs`, `outputs`, `decision`, and optional `request`, `response`, and `error`. Read the last array entry for the latest attempt. Retries, revisits, and repeated invocations of the same workflow ID append to the same arrays. `sequence` does not assert wall-clock completion order for parallel work. The selected workflow is present even when it has no settled steps; unexecuted steps are absent. A dry-run record describes simulation and has no real response.

For a workflow named `address-forecast` with a `geocode-address` step, inspect its latest declared outputs or the status history with:

```bash
jq '.workflows["address-forecast"].steps["geocode-address"].executions[-1].outputs' run.json
jq '[.workflows["address-forecast"].steps["geocode-address"].executions[].response.statusCode]' run.json
```

The optional `request` holds prepared method, URL, and headers. These headers are **not a complete wire header dump**: CLI `-H`/client defaults and transport-added headers may be absent from the runtime's prepared-request metadata. The optional `response` holds `statusCode`, headers, `contentType`, and `bodyBytes`; it has no body or preview. `contentType` is the runtime's classification (`json`, `xml`, or its `other` value), while the original media type may be present in response headers. Early transport errors can lack request metadata, and attempts without a received response lack `response`; no fabricated status code is used.

The artifact retains complete typed values for declared step and final workflow outputs, including a full response body **only when the Arazzo document explicitly declares it as an output**. An undeclared request or response body is never implicitly copied into the artifact, including through criterion-failure body previews. Trace preview limits do not truncate declared outputs. Output keys and workflow/step IDs are data; there is no expression parser for artifact paths.

Before writing, the CLI applies its existing sensitive-key policy to inputs and outputs, pattern redaction to string values and error text, header-name redaction, URL query redaction, and export-local URL userinfo redaction. This is a policy-based filter, not a guarantee that arbitrary values contain no secrets. Inspect an artifact before sharing it. `--export-run` refuses a path that aliases the trace destination, the Arazzo input, an `--openapi` input, or a local OpenAPI source loaded through `sourceDescriptions`.
