auth-flow.arazzo.yaml 
arazzo: 1.1.0
info:
  title: User Authentication Flow
  version: 1.0.0
sourceDescriptions:
  - name: api
    url: ./openapi.yaml
    type: openapi
workflows:
  - workflowId: authenticate
    inputs:
      type: object
      properties:
        username: { type: string }
        password: { type: string }
    steps:
      - stepId: login
        operationId: login
        requestBody:
          contentType: application/json
          payload:
            username: $inputs.username
            password: $inputs.password
        successCriteria:
          - condition: $statusCode == 200
        outputs:
          token: $response.body#/token
      - stepId: get-profile
        operationId: getProfile
        parameters:
          - name: Authorization
            in: header
            value: Bearer {$steps.login.outputs.token}
        successCriteria:
          - condition: $statusCode == 200
        outputs:
          name: $response.body#/name
    outputs:
      displayName: $steps.get-profile.outputs.name

New in v0.10.0

Send and receive real files: byte-exact uploads, multipart/form-data, binary downloads, and response bodies read by their declared media type.

Bytes in and out

--input-file uploads a file byte for byte, a downloaded file can feed a later step, and run --output-file saves it to disk. Bytes are never printed or traced.

Multipart uploads

Under multipart/form-data, a map payload becomes one part per entry in document order, with file parts carrying their filename and media type.

Media-type decoding

Bodies follow the declared contentType and Content-Type. Charsets, gzip, and brotli decode; nothing is sniffed or decoded lossily.

trace.v2

Traces record the parsed media type and decoded body text. Bytes appear only as size and SHA-256 descriptors, and runs that moved bytes still replay.

MCP server is back, with explicit trust

arazzo-cli serve exposes loaded workflows to an MCP client, which can run them with your credentials and no per-call approval. File reads stay inside the configured roots, and request, result, body, document, and timeout limits are flags. Hosts a workflow contacts are not restricted; see SECURITY.md.

Breaking changes

A response without a JSON Content-Type is no longer read as JSON. A literal JSON template is sent as written. Step actions no longer hide the workflow's other actions. Traces are trace.v2, so trace.v1 files no longer replay.

How It Works

Three steps from YAML to running workflows.

01

Define

Describe your workflow with the Arazzo spec and bind it to OpenAPI or AsyncAPI sources. Steps, parameters, criteria, and control flow are all declarative.

02

Run

Preview with a dry run, then execute against live APIs. Expressions resolve, retry actions fire, and control flow routes on criteria.

03

Debug

Set breakpoints in VS Code, step through workflows, and inspect variables with a full DAP debugger and watch expressions.

Features

Everything you need to run multi-step API workflows.

Run Workflows

Execute HTTP steps, resolve expressions, evaluate success criteria, and route control flow. Preview with --dry-run or run one step with --step. Upload files with --input-file and save binary responses with --output-file.

Kafka Receive

Arazzo 1.1 receive steps wait for JSON records on a Kafka topic from an AsyncAPI 3.0 source, filter on correlation IDs, and feed outputs to HTTP steps.

Parallel Execution

--parallel runs independent steps concurrently with DAG-based scheduling. Trace records keep a stable order; timing and live data can vary.

Execution Traces

trace.v2 JSON artifacts record each attempt's request, response, criteria, and routing decision, with bytes kept out as descriptors. Recognized sensitive values are redacted on a best-effort basis, so review traces before sharing.

Deterministic Replay

Re-execute traces offline with recorded responses. Request drift fails the replay, so CI catches unintended changes without a live API.

Test Suites

arazzo-cli test runs workflows from files or directories against real APIs. TAP, JUnit XML, or JSON reports, regex filtering, fail-fast, and non-zero exit on any failure.

Expressions and Selectors

$inputs, $steps, $response, $message, and interpolation, plus typed RFC 9535 JSONPath, JSON Pointer, and XPath Selector Objects. Extensions and gaps are documented.

Input Validation

Require, type-check, and enforce top-level property enums for workflow inputs. --strict-inputs makes validation errors fatal.

Generate Workflows

Scaffold CRUD workflows as YAML from OpenAPI 3.0.x specs, with standard operation targets and chained outputs. OpenAPI 3.1 and 3.2 are rejected.

Control Flow

onSuccess and onFailure actions with goto, delayed retry, and end. Sub-workflows nest up to 10 levels with input and output passing.

JSON Output

--json returns structured results, and failures carry a stable code. arazzo-cli schema prints the JSON Schema for each contract. generate writes YAML instead.

Transport Controls

Scoped TLS exceptions, redirect limits, HTTPS downgrade protection, structured transport warnings, and a built-in token-bucket rate limiter.

Why arazzo-cli

Built for reliability.

Safe

Unsafe code is forbidden across the workspace, and Clippy denies unwrap and expect. Retries, sub-workflow depth, timeouts, and response sizes are bounded, and HTTPS downgrade redirects are refused by default.

Fast

A single compiled Rust binary with thin-LTO release builds. DAG-based parallel execution runs independent steps at the same time.

Open

MIT licensed with a network-free test suite. Targets Arazzo 1.1.0 with extensions and conformance gaps documented. Embed the engine through the arazzo-runtime Rust API.

Get Started

Install, validate, run.

Install v0.10.0 from source

$ cargo install --git https://github.com/strefethen/arazzo-cli.git --tag v0.10.0 --locked arazzo-cli

Or download a prebuilt binary

# Linux x86_64, macOS, and Windows x86_64
$ gh release download v0.10.0 -R strefethen/arazzo-cli -p 'arazzo-cli-v0.10.0-*'

Get the example workflows

$ git clone --branch v0.10.0 --depth 1 https://github.com/strefethen/arazzo-cli.git
$ cd arazzo-cli

Validate, preview, and run a workflow

$ arazzo-cli validate examples/httpbin-get.arazzo.yaml
$ arazzo-cli run examples/httpbin-get.arazzo.yaml get-origin --dry-run
$ arazzo-cli run examples/httpbin-get.arazzo.yaml get-origin --verbose

Record a trace and replay it offline

$ arazzo-cli run examples/httpbin-get.arazzo.yaml get-origin --trace ./trace.json
$ arazzo-cli replay ./trace.json

Run workflows as tests in CI

$ arazzo-cli test examples/httpbin-get.arazzo.yaml --filter '^get-origin$' --format junit

Generate workflows from an OpenAPI 3.0.x spec

$ arazzo-cli generate --spec examples/swagger-petstore.openapi.json -o petstore-crud.arazzo.yaml

Validate a Kafka receive workflow without a broker (full Kafka guide)

$ arazzo-cli validate examples/kafka-order-followup.arazzo.yaml
